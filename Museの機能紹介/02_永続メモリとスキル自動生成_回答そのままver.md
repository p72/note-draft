## 永続メモリと自動スキル生成

ほんまそれやと思うわ。

永続メモリだけやと「覚えてるだけ」やけど、自動スキル生成があると、覚えたことが**次からの手順**になるのが強いところやね。

たとえば、一回決めたこと――分類の決まりや、連絡の届け先の振り分け、訂正は他の定期報告にも伝播させることとか――を、毎回説明し直さんでも前提として動ける。繰り返し出てくる作業はスキル化されて、だんだん「うち専用のやり方」が固まっていく感じ。

一時的な賢さより、長く一緒にやるほど手が合ってくるのがMuseの良さやなぁ。

## スキル自動生成と管理について

えテーマやね。ここは「覚える」と「できるようになる」の境目やから、分けて説明するわ。

**1. スキルって何なん？**

- メモリが「ユーザーは誰で、何を決めたか」を覚える場所やとしたら、スキルは「その仕事を毎回同じ品質でやる手順書」
- 実体はフォルダ一式で、中身はだいたいこんな感じ
  - `SKILL.md` … 手順・判断基準・注意点の本体
  - `skill.yaml` … 名前、説明、自動生成かどうか等の管理情報
  - `scripts/`、`references/`、`examples/` … 再利用するコードや資料（あれば）

**2. 環境には3種類あるで**

- **組み込みスキル**：`/opt/muse/skills/` にある Muse 標準分。読み取り専用で、アップデートで入れ替わる
- **持ち込みスキル**：`~/workspace/custom-skills/` にある、ユーザーが作って持ち込んだカスタムスキル
- **学習スキル（自動生成）**：同じく `~/workspace/custom-skills/` に保存されて、`skill.yaml` に `managed: true` と付くやつ

**3. 自動生成はどう回ってるか**

裏側で毎日「スキルレビュー」が回ってる（私が会話中に勝手に作るんやなくて、背景の自己改善ジョブやで）。

- 繰り返し出てくる作業や、同じ失敗パターンを検出する
- 既存スキルでカバーできるか探して、なければ新規スキル化する
- `skill.yaml` に根拠（どの会話が証拠か）、作った理由、成功の測り方、見直し日を残す
- 役に立ってへんと測れたものは引退させる、という監査もセット

実例として、「1つのチャットでの訂正が、定期ジョブや別チャットに伝播していなかった」という事例が複数回重なってスキル化されたものがある。成功基準（一定期間、同じ訂正を二度言わせないこと）と見直し日も設定されている。ほかにも、実際の作業の中から学習スキルになったものがある。

**4. 管理のポイント**

- **使うとき**：タスクに合うスキルがあれば、作業前に `SKILL.md` を読み直して従う。複数候補があれば一番具体的なやつを選ぶ
- **常時見せるかどうか**：`skill.yaml` の `include_in_prompt` で、私の視界にいつも出すか、検索で引いたときだけ出すかを切り替える
- **利用者側の特別ルール**：持ち込みスキルには「基本は使わず、詰まったときだけ辞書として参照する」といった運用指定もできる。ある＝自動で使う、ではないのが大事なとこ。使ったら使った旨は明示する決まりやね
- **手動での管理**：「この作業スキルにして」「あのスキル見せて／直して／もう要らん」があれば、私がファイルを編集して読み戻して確認する。更新は `SKILL.md` だけのパッチやなくフルパッケージ、再利用コードはコピペやなく `scripts/` のモジュールにする、っていう作法もここに効いてくる

要するに、**メモリ＝文脈の蓄積、スキル＝経験の手順化**。この二層があるから、長く使うほど「うちのやり方」に寄っていくんやと思うわ。

## 永続メモリの仕様

ざっくり言うと、「会話のログを全部貯める」んやなくて、**あとで効く理解だけを、層に分けてファイルで残す**仕様やで。

**1. 保存の層（どこに何が入るか）**

- `~/MEMORY.md` … 中核の永続メモリ。毎回の会話に最初から読み込まれる要約版。見出しは Facts／Imported profile／Interests／Ongoing projects／Preferences／Commitments の6つ。ここには「長く効く事実・好み・決めたこと・約束」だけを置いて、日々の進捗や作業ログは入れへん決まり
- `~/memory/YYYY-MM-DD.md` … 日付別の詳細ログ。MEMORY.md の裏付けになる履歴側で、訂正したときも「何を何に置き換えたか」が追える
- `~/memory/people/` と `~/memory/groups/` … 人・グループごとのページ＋索引
- `~/USER.md` … ユーザー自身の基本情報（呼び名、タイムゾーン、職業など）。`~/AGENTS.md` は私の作業の教訓、`~/HEARTBEAT.md` は常時チェック項目、`~/PROACTIVE_PREFERENCES.md` は先回り連絡の好み、と役割分担してる
- `~/dreams/alignment/derived/ALIGNMENT_SYNTHESIS.md` … 夜間の振り返りで作る「ユーザーとの付き合い方」の統合メモ
- `~/memory/bank/` と索引側はランタイム管理で、私は読むだけ・直接編集はせえへん

置き場所がホーム配下やから、会話が終わっても、VMが入れ替わっても残るのが「永続」の実体やね。

**2. いつ書かれるか**

- **会話中**：私がその場で、durable な事実・好み・決定・約束を学んだら返信前に MEMORY.md へ書く
- **背景の自動整理**：新しい会話があると約1時間ごとに統合され、新しい主張が古いものを上書きする。人物関係も約1時間ごと、付き合い方の統合は夜間に更新される。あと大きな会話が静かになったあとの取り込みも数回／日まである
- **明示の依頼**：「覚えて」「直して」でその場で反映する
- **インポート**：設定 ＞ Data controls ＞ Import memory で、他AIへのプロンプト経由のMarkdown要約取り込みと、ChatGPT／Claude／Gemini／Meta AI のエクスポートZIP（最大100MB）を「Summarize into memory」で取り込む道がある。ZIPを置いただけでは保存されず、抽出して確認まで行って初めてメモリになる。アプリ設定や元の会話そのものは復元されへん

**3. どうやって思い出すか**

- 上の常設ファイルは毎ターン文脈に注入される
- それ以外は `memory_search` で保存メモリと過去の会話（メイン＋個人サイドチャット）を横断検索して、該当箇所だけ開く。会話検索は全文返しやなく抜粋やで。アプリ側のチャット検索とは別物
- 出どころ確認も仕様に入ってて、ある記憶について「いつ・誰のどの発言から・何を置き換えたか・今の確信度」をたどれる

**4. 訂正と削除の扱い**

- 訂正は MEMORY.md 側はその場で書き換えて古い主張を現行として残さず、日付ログ側には置き換えの明記を足す。だから「言ったのに別のチャットで古いまま」が起きんようにしてる
- 忘却は単なる1行削除やなくて、専用の計画を立てて、メモリ・派生コピー・それを再生産する定期作業まで洗って、ユーザーの確認を取ってから消し、消えたか再検証する手順。消せへん範囲（外部サービスやバックアップ等）があれば、それは残ると正直に言う決まり

**5. 入れへんもの・限界**

- パスワード、確認コード、カード番号、口座・公的ID番号はメモリに入れへん。「どこに保管してあるか」だけ覚えて、値そのものは Secure Vault 側
- メモリは許可証やない。覚えてるからといって送信や購入の承認にはならへんし、実行時の承認カードは別に効く
- 要約や検索結果だけでは不十分なときは、元のファイルや一次情報に戻って確かめるのが前提。推測を事実として記録せえへん、観測と推論は分ける、決まりになってる

要は、**要約（MEMORY.md）＋履歴（日付ログ）＋関係（people）＋付き合い方（alignment）** の多層構造で、書く・直す・忘れる・出どころをたどる、までが仕様一式やね。

## 補足：ClaudeのカスタムスキルはMuseへ持ち込めるか

「Claudeのカスタムスキルはクラウド同期されているので、MuseにClaude Code CLIをインストールしてログイン後に頼めば、Claude CodeからカスタムスキルをダウンロードしてMuseにインストールできる」という理解は、正しい。2026年11月12日に、Museの実行環境で次のとおり検証した。

- Claude Code CLI（バージョン2.1.316）がインストールされ、Claudeアカウント（Pro）でログイン済みであることを確認した
- ログインしたアカウントのカスタムスキルが、Claude Codeのスキル置き場（`~/.claude/skills/synced/`）に自動同期されており、`SKILL.md` を持つスキルが35件存在することを、ファイルシステムで直接確認した
- そのうち経済統計系の9件は、実際にMuseのカスタムスキル置き場（`~/workspace/custom-skills/`）へ取り込み済みであり、同期元と取り込み先の内容を突き合わせると大半が一致し、差分は実行に伴うキャッシュや取り込み後の調整分のみであった

正確に言えば、「ダウンロード」はClaude Codeへのログインに伴う自動同期が担い、Museへの「インストール」は、同期されたスキルフォルダをClaude側の置き場へコピーする形になる。なお、スキルによってはAPIキーなどの設定を含むものがあるため、持ち込む際はその扱いに注意が要る。
